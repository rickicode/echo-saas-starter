# SaaS starter kit fix verification and residual concerns (v2)

Seven of the nine v1 issues have been addressed. Two original issues remain unaddressed (cross-plugin coupling, hardcoded role_id=3), and the RequireRole fix introduced a new problem: it calls an API endpoint that doesn't exist.

**Watch for:** The `RequireRole` component now fetches `GET /roles/me`, but no such endpoint is registered in the roles plugin — every role check will 404 and fall through to "no permission" (confirmed). The PASETO secret validation allows an empty string through, deferring the failure to first token generation (confirmed). Concurrent token refresh attempts can race against rotation, logging the user out unexpectedly (likely).

## High-level view

The RequireRole component now fetches user roles from the backend and does proper set-intersection checking. The problem is that the endpoint it calls (`/roles/me`) was never added to the roles plugin's route registration. The existing endpoint that could serve this purpose is `GET /api/v1/roles/users/:id/roles`, which requires knowing the user's ID. The admin panel is effectively inaccessible.

The PASETO secret validation catches short secrets but allows empty strings. Since the `.env.example` shows `PASETO_SECRET=` with no default value, a developer who starts the app without setting it will get past config validation but hit an opaque error on first login.

The token refresh retry terminates safely (the recursive call omits `retryFn`, so a second 401 hard-redirects to login). However, if two concurrent requests both trigger refresh simultaneously, strict token rotation means the second refresh attempt sends an already-deleted token and fails — logging the user out despite having a valid session.

<summary>Issues (4)</summary>

1. **RequireRole calls nonexistent endpoint** — The component fetches `GET /api/v1/roles/me` but the roles plugin only registers `GET /api/v1/roles`, `POST /api/v1/roles/:id/assign`, `DELETE /api/v1/roles/:id/users/:user_id`, and `GET /api/v1/roles/users/:id/roles`. Add a `GET /me` route to the roles plugin that returns the current user's roles, or have the component use the existing `/roles/users/:id/roles` endpoint with the user ID from auth context.
2. **Empty PASETO_SECRET passes validation** — `config.Load()` only checks length when `PasetoSecret != ""`. An empty secret (the default) passes config validation but fails at `symmetricKeyFromSecret` during first token generation. Either require `PASETO_SECRET` to be set (like `DATABASE_URL`), or generate a random key on startup with a warning log.
3. **Concurrent refresh rotation race** — If two API calls both get 401 simultaneously, both call `attemptTokenRefresh`. The first succeeds and rotates (deletes) the old refresh token. The second sends the now-deleted token, fails, and redirects to login. For a starter kit, document this or add a refresh mutex/deduplication.
4. **Hardcoded role_id=3 in registration** — Still present and unaddressed from v1. The auth handler inserts `role_id=3` into `user_roles` assuming role 3 is "user". If the roles plugin migrations haven't run or role IDs change, registration succeeds but the role assignment silently fails (error discarded with `_ =`).

## RequireRole calls a ghost endpoint

The `RequireRole` component fix correctly fetches roles and performs set-intersection logic:

```typescript
get<{ roles: UserRole[] }>('/roles/me')
  .then((data) => {
    const roleNames = data.roles.map((r) => r.role_name)
    setUserRoles(roleNames)
  })
```

The roles plugin's `RegisterRoutes` registers these paths (under the `/api/v1/roles` group):

```go
g.GET("", p.handlers.ListRoles, authMiddleware)
g.POST("/:id/assign", p.handlers.AssignRoleHandler, authMiddleware, adminMiddleware)
g.DELETE("/:id/users/:user_id", p.handlers.RemoveRoleHandler, authMiddleware, adminMiddleware)
g.GET("/users/:id/roles", p.handlers.GetUserRolesHandler, authMiddleware)
```

No `/me` route exists. The request falls through to the SPA handler (which serves `index.html` for all `GET /*` routes not matched by API groups). The response is HTML, `response.json()` throws, the `.catch()` branch executes, `setUserRoles([])` fires, and every user sees "You do not have permission to access this page" regardless of their actual roles. The admin panel is locked out for all users. (confirmed)

## PASETO secret empty-string gap

```go
if cfg.PasetoSecret != "" && len(cfg.PasetoSecret) < 32 {
    return nil, fmt.Errorf("PASETO_SECRET must be at least 32 bytes long")
}
```

When `PASETO_SECRET` is unset, this check passes. `symmetricKeyFromSecret` fails with "secret must be at least 32 bytes" during first token generation. The error surfaces as `AUTH_016 "Failed to generate token"` on the first registration or login attempt — a runtime failure instead of a startup failure. A developer clones the repo, runs `make dev`, tries to register, and gets a generic error with no indication that `PASETO_SECRET` needs to be configured. (confirmed)

## Concurrent refresh token rotation race

The refresh flow deletes the old refresh token before issuing a new one. Two concurrent 401s from the same page (common when a dashboard loads multiple API calls simultaneously) will both race to refresh. The first wins; the second sends a deleted token and gets rejected. The user is redirected to login despite the first refresh having succeeded.

The fix would be either a client-side refresh mutex (queue subsequent refresh attempts behind the first in-flight one) or a server-side grace period (keep old refresh tokens valid for a few seconds after rotation). For a starter kit, a comment explaining the limitation is sufficient, but the current code has no such comment. (likely)

## Placeholder rewriter escaped-quote edge case

The `RewritePlaceholders` function toggles `inSingleQuote` on every `'` character. Standard SQL escapes single quotes by doubling them: `'it''s'`. The rewriter would see the doubled quote as "exit string then re-enter string", which happens to produce the correct result for `''` (even number of toggles). However, if a `?` appears between an odd-positioned escaped quote sequence and the real string end, it would be incorrectly rewritten. The starter kit's queries don't contain escaped quotes, making this a theoretical gap. (possible)
